# World generation (ChunkService)
Tier: standard
Purpose: One seed -> deterministic 8x8 chunk layout in four biome rings (variants per biome from shared/data/Chunks) with tree/rock/ore/food/spawn-zone slots, POIs and a camp site; chunks stream in/out around players. Phase 3 adds POIs, warm spots, thin ice, fog-of-war map, and node state that survives unload.
Owner files: src/server/World/{ChunkService,PoiService,BiomeService,MapService}.luau, src/shared/logic/{WorldLayout,BiomeLogic,FogMap}.luau, src/shared/data/{Biomes,Chunks}.luau, src/server/Phase3/WorldGenBoot.luau, src/client/Phase3/WorldGenClient.luau, src/client/Map/MapView.luau, tests/{WorldTests,BiomeTests}.luau. Config.World is brief 12's (read only).
Public API: WorldLayout.generate(seed, params) -> Layout; .serialize, .streamDiff, .ringOf, .ringPosition, .distanceToChunk (pure). ChunkService.start/stop, .ensureLoadedAround(x, z), .getCampPosition() -> Vector3?, .getSeed(). DebugService command "teleportRing" (1 = start forest, outward, clamped).
Data touched: Workspace attributes WorldSeed (number), CampPosition (Vector3). Tag Config.World.ChunkTag on chunk Models (attrs ChunkIndex, Ring, Variant, Rotation). Slot parts tagged per Config.World.SlotTags (TreeSlot, RockSlot, FoodSlot, SpawnZoneSlot). Workspace.Chunks and Workspace.Camp folders.
Invariants: same seed + params -> identical layout (serialize equal); camp chunk is in StartForestRing; camp has CampGuaranteedWood/FoodCount resources within CampGuaranteeRadius, all inside the camp chunk; load within StreamInRadius, unload only beyond StreamOutRadius of every player; camp chunk is never unloaded; the server never builds all 64 chunks at once.
Exploit surface: no remotes. teleportRing is Studio-only via DebugService (validated + rate limited there).
Playtest checklist: 1. Studio play: Workspace.Chunks has only chunks near the camp. 2. Walk away: far chunks unload, new ones load. 3. DebugService.run teleportRing 1..4: player lands in the matching ring and chunks load. Script: tools/qa/runner.luau (scenario world). Headless: lune run tests/run.
Status: in progress (Phase 3 brief 13)

## Phase 3 additions
- **Variants.** Each chunk takes biome = Biomes.forRing(ring); the variant is a seeded weighted pick from Chunks.forBiome(biome) and a 0..3 rotation. Slot counts (trees, rocks, ore, food, spawn zones, POI slots) come from the variant. Layout chunk fields: biome, variantId, ore, pois.
- **Rings.** BiomeLogic.ringAt(x, z) = floor(max(|x|,|z|) / ChunkSize) clamped to the outer ring; equals WorldLayout.ringOf for the chunk holding the point. drainMultiplier(ring, resistance) = severity * max(MinDrainFraction, 1 - perPoint*resistance) * min(MaxUnderdressed, 1 + shortfall*perPoint), all capped by Config.Biome.
- **Camp.** Camp chunk is a ring == Config.World.StartForestRing chunk (now 0, the 2x2 centre; brief 12 moved it from 1). Camp guarantee (wood trees + food within CampGuaranteeRadius, same chunk) is tested over many seeds with the live Config.World.
- **POIs.** Kinds cabin, plane, cave, campsite, ruin (loot crate), hotspring (warm), thinice (patches). Loot tier = BiomeLogic.lootTier(distance from camp) = clamp(1 + floor(d / ChunkSize), 1, 4); contents deterministic from (seed, poi id), tables in Biomes.Loot; never decreases with distance. Crates are looted once per run.
- **Warm spots.** Cabin hearth: ProximityPrompt adds 1 Wood = HearthBurnSeconds of warmth (capped at HearthMaxSeconds); while lit it carries Config.WarmSpot.Tag + attribute WarmSpotRadius = CabinRadius. Hot springs always carry the tag with HotSpringRadius and attribute WarmSpotKind = "HotSpring" (mobs bias is brief 16's).
- **Thin ice.** Frozen-lake patches (tag ThinIce). Standing on one for ThinIceCrackSeconds sets Cracking, then it breaks once: small damage to players on it and onThinIceBreak callbacks fire (cold-shock is brief 18's). Broken stays broken.
- **Node persistence (KNOWN_ISSUES fix).** ChunkService keeps memory[slotKey] = { depletedAt, hits } outside the chunk model. A reloaded node that was depleted stays hidden and unregistered until Config.Gather.RespawnSeconds since depletion (wall clock continues while unloaded), then reappears; partially hit nodes keep HitsLeft. Memory is cleared on stop().
- **Ring attribute.** BiomeService sets Player BiomeRing every Biome.UpdateInterval.
- **Map.** MapService: per-player explored cells (FogMap), MapRequest (needs Config.Map.ItemId, Guard.rateLimit Net.MapRateInterval) -> MapData explored cells only; markExplored(position, radius). Client Map/MapView (M key + button) draws explored cells and the player dot.
- **Hidden state.** Nothing hidden (dread, events) is read or shown here. Tuning constants live in BiomeLogic.Tuning because Config is brief 12's; brief 18 may move them.
- **Exposes (Phase 3).** BiomeLogic.ringAt/drainMultiplier/lootTier; BiomeService.getRing(player)/getBiome(player)/onRingChanged(cb); MapService.markExplored(pos, radius); PoiService.onThinIceBreak(cb)/setHearthWoodItem; ChunkService unchanged API.
- **Tests.** tests/BiomeTests.luau: determinism, ring math, loot monotonic, camp guarantee, variants per biome, node memory, hearth cap, thin ice, fog map.

## Integration points
- Exposes: getCampPosition(), getCampSpawnPosition() (Spawn provider), getCampFire() (camp campfire Part in Workspace.Camp, tagged Config.Fire.Tag), ensureLoadedAround, getSeed; Workspace attrs Config.World.SeedAttribute / CampAttribute (HUD compass).
- Consumes: GatherService.registerNode(slot, "Tree"|"Rock") for every tree/rock slot it builds (tier + respawn from Config via ItemCatalog.Nodes); DebugService.register("teleportRing"). Slot tags live in Config.World.SlotTags (WorldLayout.SlotKinds aliases them).
- Started before SpawnService so the camp exists before any LoadCharacter. Tree/rock slots are visible block-out parts; other slots stay invisible.

## Terrain (implementation)

- Pure height field: `shared/logic/World.luau` (`heightAt`, `blockHeight`, `amplitudeAt`, `shouldKill`). Config: `Config.Terrain` (incl. `ColumnDepth`).
- Adapter: `server/World/TerrainBuilder.luau` writes Roblox Terrain voxels per chunk (one FillBlock per same-height run along X; Air clear on unload). Voxels are not parts, so they do not count toward `Perf.MaxLiveParts`. The old `Ground` part is gone.
- Use `ChunkService.heightAt(x, z)` (camp-aware) for placing anything on the ground; camp spawn/fire are at BaseHeight (flat area).
- Falls: `ChunkService.setFallHandler(fn(player))` is called once per player below KillHeight / past the edge (checked each stream tick). Integration must wire it to the run-end/downed logic as "gone, not revivable". Mobs: no hook yet; integration should despawn mobs where `World.shouldKill(x, y, z)`.
- Tests: `tests/TerrainTests.luau` (determinism, step cap over ALL blocks for 3 seeds x 2 camps, biome amplitude, edge/kill).

## Trees (TreeBuilder, ForestPlacement, TreeRules)
- `TreeRules.shape(height)` gives the vertical layout: bare trunk to `foliageBottom` = clamp(0.4*height, minCanopyBottom, height-MinFoliageThickness), capped at `MAX_BARE_TRUNK` (18) because the trunk Part is the gather node (GatherService measures to its centre, Gather.Range 12). Trunk Part height = bottom + 2 (reaches into the foliage). Foliage: wide lower tier (60% of the foliage thickness) + narrower upper tier to the top.
- `TreeBuilder.createTree` builds 3 parts: trunk (CanCollide, the gather node, tag attribute unchanged, depletion hides descendants) + FoliageLow/FoliageTop children (`TreeRules.FOLIAGE_FLAGS`: CanCollide/CanQuery/CanTouch all false). `ForestPlacement.Tree.foliageBottom` is exposed; rng order unchanged so placement is identical.
- Tests: tests/LivePartsTests.luau (heights, clearance, collide flags, node reach, parts per tree, live-parts estimate).

## Massive structures + loot wiring (integration round)
- Placement: `shared/logic/MassivePlacement.plan(layout)` (pure, seeded; ground from World.heightAt, never from carved Terrain). Per `Config.Massive.Ids`: count CountMin..CountMax, ring in `Rings`, radius `MassiveRules.footprintRadius`, centres >= `MinSeparation` from each other and from the camp (so the spawn pad), clear of every POI footprint (+PoiMargin), inside the world edge (+EdgeMargin), relief <= `MaxSiteRelief`, deepest carve >= `KillMargin` above `Terrain.KillHeight`. `ChunkService.start` computes `sites`; `ChunkService.getSites()`.
- Exclusion: trees via `ForestPlacement.poiClears(layout, chunk, extra)` (`MassivePlacement.clears`); rocks/ore/food/spawn-zone slots inside a footprint are skipped (`MassivePlacement.blocks`). Ground decor patches are not filtered.
- Chunk hooks for the builder: `ChunkService.isLoaded/isTerrainReady/generation(index)/refreshTerrain(index)/setExtraPartsProvider`. `generation` counts chunk (terrain) builds; `isTerrainReady` = loaded and the TerrainBuilder tick-budget queue has nothing pending for it.
- `server/World/MassiveService.luau` (started from init.server after Wiring.apply): ONE Heartbeat loop at `DressingCheckInterval` for all structures and players: (1) a structure whose covering chunk unloaded or was rebuilt is destroyed and its still-loaded neighbours get `refreshTerrain` (carved voids/pad cleared), (2) one eligible site per tick is built (all covering chunks terrain-ready, nearest to a player first, at most `MaxLiveStructures`), (3) `Handle.Update(playerPositions)`. Builders run under pcall; a failing site is skipped for the run. Live structure parts (Budget.Parts + chests) are reported to ChunkService so streaming stays under `Perf.MaxLiveParts` (outer chunks defer while structures are live).
- Loot: chest slots -> `LootService.RegisterChest({Position, Depth, StructureType, Ring = site ring, Index, ChunkKey})` parented to the structure model; art via `LootService.SetArtBuilder(ChestArt.build)`; `LootService.start()` at boot; `LootService.ResetRun(seed)` at start, `ResetRun(nil)` + all structures destroyed on `RunLifecycleService.onRunEnded`. Opened chests are remembered for the run (rarity) so a rebuilt structure shows them open and empty, never refilled.
- Temple `DreadListener` -> nearest player within DressingSpawnRadius gets `DreadService.addSighting(player, GainLurkerSighting * Config.Massive.TempleDreadScale)`. LurkerSpots / CueSpots are not wired (no existing server API takes spots).
- Carving vs streaming: only StructureKit* write Air to Terrain; nothing reads voxels (placement and `ChunkService.heightAt` use pure World.heightAt). Chunk unload clears voxels, so a carve in an unloaded chunk is lost; MassiveService rebuilds when all covering chunks are ready again. Tests: tests/MassiveWiringTests.luau, tests/LivePartsTests.luau.
- Perf: `Config.Art.World.ChunkDecorBudget` 48 -> 16. Estimate (3 seeds, art caps): full 5x5 window 4894 + 400 allowance = 5294; 3x3 core + 2 largest structures + chests = 4736; limit 5400 (cap 6000, unchanged). Full window + 2 live structures can still exceed the cap; ChunkService defers the outer chunks then.

## Items round: site grounding (SiteGround), one live structure, spawn exclusion
- `shared/logic/SiteGround.luau` (pure, tests/SiteGroundTests.luau): samples the whole footprint (grid every `Config.SiteGround.SampleStep` incl. corners, edge midpoints, centre), min/max/median, range, slope, max adjacent jump (cliff), water fraction. `evaluate` rejects Water / Cliff / Range (> MaxRange) / Slope; otherwise `level` (range <= FillRange, base = median, cut + fill) or `foundation` (base = highest sample). `relocate` searches rings inside RelocateRadius; `targetHeight` blends back to the original ground over `SkirtWidth` (no hard edge); `snapGround` / `snapY` = highest surface under a placeable footprint + `SinkMargin`.
- Adapter `server/World/SiteGroundTerrain.apply(plan, heightFn)`: levels the voxel columns (biome material, row-merged FillBlock). StructureKitA/B call it before carving; the old grey Rock/Slate `Kit.pad` fill (the hard-outlined pad sunk in the snow) is gone (pad dims only size the levelled area). `MassivePlacement.plan` rejects sites that fail SiteGround in either yaw (the 400-attempt loop relocates).
- Placement: `PlacementService` and the client ghost both use `SiteGround.snapGround` (rays at the footprint's corners, edges and centre; highest hit + SinkMargin). POI sites already use the highest sample + foundation (PoiPlan.siteFloor), unchanged.
- `Config.Massive.MaxLiveStructures = 1`: MassiveService streams the live structure out (destroys it) when no player is within radius + DressingDespawnRadius and a nearer site is waiting. Interior dressing stays lazy near players. Parts estimate (LivePartsTests): 3x3 core + 1 structure + chests <= 90% of 6000.
- Mob spawns: `MobService.setSpawnBlocker` (wired by MassiveService) skips natural spawns inside any massive site footprint.
- Gather reach: `TreeRules.reachDistance` measures to the node surface (trunk radius, half height), used by GatherService, so giant trunks are choppable from the ground (bare-trunk cap MAX_BARE_TRUNK kept).
- Kit B chests stand on the room floor (`PlanKitB.chest` y = room.y, validated), matching Kit A.
